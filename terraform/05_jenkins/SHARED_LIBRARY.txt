# Jenkins Shared Library — what it is and why we use it
#
# Repo: https://github.com/oliversims/jenkins-shared-libraries
# Used by: Jenkins (configured as Global Pipeline Library name "Shared")
# Called from: Jenkinsfile via  @Library('Shared') _
#
# ═══════════════════════════════════════════════════════════════════════════════
# WHAT IT IS
# ═══════════════════════════════════════════════════════════════════════════════
#
# A Jenkins Shared Library is a separate Git repo of reusable Groovy helper
# functions. Instead of putting long shell/Groovy blocks in the Jenkinsfile,
# the pipeline calls short functions like clean_ws() or docker_build(...).
#
# Those functions live under:
#   jenkins-shared-libraries/vars/*.groovy
#
# Each file name becomes a callable step:
#   vars/clean_ws.groovy           →  clean_ws()
#   vars/docker_build.groovy       →  docker_build(...)
#   vars/update_k8s_manifests.groovy → update_k8s_manifests(...)
#
# Jenkins loads this repo when you configure:
#   Manage Jenkins → System → Global Pipeline Libraries
#   Name:              Shared          (must match @Library('Shared'))
#   Default version:   main
#   Project repository: https://github.com/oliversims/jenkins-shared-libraries.git
#
# ═══════════════════════════════════════════════════════════════════════════════
# WHAT IT IS USED FOR
# ═══════════════════════════════════════════════════════════════════════════════
#
# This project's Jenkinsfile is a CI pipeline that:
#   1. Cleans the workspace
#   2. Clones the app repo
#   3. Builds Docker images (app + migration)
#   4. Runs tests
#   5. Runs a Trivy security scan
#   6. Pushes images to Docker Hub
#   7. Updates Kubernetes YAML image tags and pushes that change to GitHub
#
# The shared library implements those steps so the Jenkinsfile stays short and
# the same helpers can be reused by other pipelines later.
#
# Without this library configured (or with the wrong Name / URL), the pipeline
# fails immediately with errors like: No such DSL method 'clean_ws'.
#
# ═══════════════════════════════════════════════════════════════════════════════
# WHAT IT CONTAINS (vars/)
# ═══════════════════════════════════════════════════════════════════════════════
#
# clean_ws.groovy
#   Clears the Jenkins job workspace before a new build (cleanWs()).
#
# clone.groovy
#   Clones a Git repo/branch into the workspace.
#   Jenkinsfile uses it for tws-e-commerce-app_hackathon on master.
#
# docker_build.groovy
#   Runs `docker build` for a given image name, tag, Dockerfile, and context.
#   Also tags the image as :latest.
#
# docker_push.groovy
#   Logs into Docker Hub with Jenkins credentials (default ID:
#   docker-hub-credentials) and pushes :<tag> and :latest.
#
# run_tests.groovy
#   Placeholder for unit tests (currently echoes success; add real test
#   commands here if/when needed, e.g. npm test).
#
# trivy_scan.groovy
#   Runs `trivy fs .` on the workspace (filesystem vulnerability scan).
#
# update_k8s_manifests.groovy
#   Updates image tags in kubernetes/ YAML, commits, and pushes to GitHub
#   using github-credentials. That lets Argo CD (later) pick up new tags.
#
# Also present (not used by this Jenkinsfile):
#   hello.groovy
#   generate_reports.groovy
#
# ═══════════════════════════════════════════════════════════════════════════════
# HOW IT CONNECTS TO THIS PROJECT
# ═══════════════════════════════════════════════════════════════════════════════
#
# Jenkinsfile (in tws-e-commerce-app_hackathon)
#   → @Library('Shared')
#   → calls clean_ws / clone / docker_build / run_tests / trivy_scan /
#     docker_push / update_k8s_manifests
#
# Jenkins credentials (must exist):
#   docker-hub-credentials  → used by docker_push
#   github-credentials      → used by update_k8s_manifests (and Git clone if needed)
#
# Setup steps: terraform/RESTORATION.txt  →  PHASE 1b  →  Step 5 Shared library
#
# ═══════════════════════════════════════════════════════════════════════════════
# IMAGE TAG UPDATES (why file names matter)
# ═══════════════════════════════════════════════════════════════════════════════
#
# After Jenkins builds and pushes a new Docker image (for example :7), the last
# pipeline stage asks the shared library to edit the Kubernetes YAML files so
# they point at that new tag, then commit/push to GitHub.
#
# The YAML files that hold those image lines in THIS project are:
#   kubernetes/easyshop-deployment.yaml   →  simsoliver/easyshop-app:<tag>
#   kubernetes/migration-job.yaml        →  simsoliver/easyshop-migration:<tag>
#
# The shared library function update_k8s_manifests.groovy must open THOSE exact
# file paths. If it opens different file names, it will not find the image lines
# to change, so Argo CD will keep deploying the old tag.
#
# Check in:
#   https://github.com/oliversims/jenkins-shared-libraries
#   → vars/update_k8s_manifests.groovy
# that the sed paths use easyshop-deployment.yaml and migration-job.yaml.
#
# ═══════════════════════════════════════════════════════════════════════════════
# FULL FLOW (end to end)
# ═══════════════════════════════════════════════════════════════════════════════
#
# You click Build Now on the EasyShop job in Jenkins.
# Jenkins loads the shared library named "Shared", then runs the Jenkinsfile.
#
#   [1] Cleanup Workspace
#         clean_ws()
#         → empties the Jenkins job workspace
#
#   [2] Clone Repository
#         clone(app-repo, master)
#         → downloads tws-e-commerce-app_hackathon into the workspace
#
#   [3] Build Docker Images  (parallel)
#         docker_build(easyshop-app) + docker_build(easyshop-migration)
#         → creates local images tagged with BUILD_NUMBER (e.g. :7) and :latest
#
#   [4] Run Unit Tests
#         run_tests()
#         → placeholder test step (extend later if needed)
#
#   [5] Security Scan with Trivy
#         trivy_scan()
#         → scans the workspace filesystem for vulnerabilities
#
#   [6] Push Docker Images  (parallel)
#         docker_push(...) using docker-hub-credentials
#         → uploads images to Docker Hub:
#              simsoliver/easyshop-app:<BUILD_NUMBER>
#              simsoliver/easyshop-migration:<BUILD_NUMBER>
#         Where to see them:
#              https://hub.docker.com/r/simsoliver/easyshop-app/tags
#              https://hub.docker.com/r/simsoliver/easyshop-migration/tags
#
#   [7] Update Kubernetes Manifests
#         update_k8s_manifests(...) using github-credentials
#         → edits image lines in:
#              kubernetes/easyshop-deployment.yaml
#              kubernetes/migration-job.yaml
#         → commits and pushes to GitHub (master)
#         Where to see the new tag:
#              those two YAML files on GitHub
#
#   [8] GitOps deploy (after Argo CD is set up — not part of Jenkins itself)
#         Argo CD watches the GitHub repo path kubernetes/
#         → sees the new image tags in Git
#         → syncs them into the EKS cluster (namespace easyshop)
#         Where to see them running:
#              Argo CD UI (easyshop app)
#              kubectl get deploy -n easyshop -o wide
#
# Picture:
#
#   Jenkins (EasyShop job)
#      │  uses shared library helpers
#      ▼
#   Build images locally ──► Push to Docker Hub
#      │
#      ▼
#   Update kubernetes/*.yaml tags ──► Push commit to GitHub
#      │
#      ▼
#   Argo CD syncs Git ──► EKS runs pods with the new image tag
#
# Tag source of truth for each build = Jenkins BUILD_NUMBER
# (build #7 → image tag :7).
